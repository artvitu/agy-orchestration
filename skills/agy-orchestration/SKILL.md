# Оркестрация в Google Antigravity (`agy-orchestration`)

В `Google Antigravity Desktop 2.34+` штатный инструмент `send_message` работает только внутри дерева одной сессии (между родителем и его собственными дочерними субагентами). Этот навык даёт двухэтажную оркестрацию:
1. **Верхний этаж (между вкладками в левой боковой панели):** скрипт `scripts/agy-wake.py` рядом с этим файлом `SKILL.md` общается с локальным `LanguageServerService` (`~/.gemini/antigravity/daemon/hub_*.json`) и позволяет находить сессии, вести реестр ролей, будить спящие вкладки (`IDLE`), ставить сообщения в очередь занятым вкладкам (`RUNNING` -> `WHEN_IDLE`) и создавать новые сессии сразу внутри нужного проекта.
2. **Нижний этаж (внутри одной сессии):** постоянные ролевые субагенты (`define_subagent` + `invoke_subagent` + `send_message`) удерживают память роли и `88-96%` промпт-кэша между кругами правок даже после сжатия родителя (`/compact`).

## Требования и расположение скрипта

- Требуется запущенный **`Google Antigravity Desktop 2.34+`** и **`Python 3.10+`** (проверено на macOS; полную справку по флагам всегда можно посмотреть через `--help`).
- Запускай команды из корня рабочего репозитория (скрипт автоматически сопоставит имя папки с проектом в Antigravity) либо передавай явный `--project <имя>`.
- Скрипт `agy-wake.py` (и его модуль `model_context.py`) лежит в подпапке `scripts/` **в той же директории `<SKILL_DIR>`, что и этот файл `SKILL.md`**. Возьми каталог этого `SKILL.md` из блока `<skills>` и вызывай:

```bash
python3 "<SKILL_DIR>/scripts/agy-wake.py" <команда> [флаги]
```

Никаких сторонних pip-пакетов не требуется.

## Важное условие для исходящих вызовов: сетевая песочница macOS (`TURBO`)

Стандартная песочница macOS Seatbelt внутри инструмента `run_command` блокирует исходящие TCP-сокеты к `127.0.0.1` с ошибкой `Operation not permitted`. Чтобы агент сам мог будить соседние вкладки через `agy-wake.py`:
- либо вкладка-отправитель должна быть переведена в пресет **`TURBO`** (`AGENT_PERMISSION_PRESET_TURBO`; учитывай, что `TURBO` также включает автоподтверждение терминальных команд в этой вкладке, а вернуть стандартный режим можно через `--preset auto`):
  - при создании новой сессии передавай `--preset turbo`;
  - для уже открытой сессии пользователь может один раз выполнить в обычном терминале (вне песочницы):
    ```bash
    python3 "<SKILL_DIR>/scripts/agy-wake.py" preset --to "<заголовок или UUID>" --preset turbo --yes
    ```
  - либо переключить режим разрешений сессии в интерфейсе `Antigravity`;
- либо команда `run_command` вызывается с обходом песочницы по разрешению пользователя.

Если `agy-wake.py` сообщает о блокировке `127.0.0.1` песочницей - не гадай и не пытайся перезапускать приложение, а подскажи пользователю команду `preset --preset turbo --yes` выше.

## Команды верхнего этажа (`agy-wake.py`)

Все изменяющие команды (`send`, `spawn`, `bind`, `unbind`, `preset`, `delete`, `discover --sync`) без флага `--yes` выполняют безопасный сухой прогон (`dry-run`) и показывают, что именно произойдёт.

### 1. Осмотреться и собрать реестр ролей

```bash
# Список корневых сессий текущего проекта (дочерние субагенты скрыты по умолчанию)
python3 "<SKILL_DIR>/scripts/agy-wake.py" list

# Автоматически собрать реестр ролей из живых вкладок текущего проекта:
# распознаёт теги [role:backend] в первых сообщениях, префиксы "[backend] ..." в заголовке,
# а с флагом --from-titles строит понятные kebab-case имена из заголовков вкладок
python3 "<SKILL_DIR>/scripts/agy-wake.py" discover --from-titles --sync --yes

# Посмотреть текущий реестр ролей и их живой статус (IDLE / RUNNING / MISSING)
python3 "<SKILL_DIR>/scripts/agy-wake.py" registry

# Вручную привязать роль к конкретной вкладке по части заголовка или UUID
python3 "<SKILL_DIR>/scripts/agy-wake.py" bind --slug reviewer --to "Ревью кода" --yes
```

По умолчанию реестр сохраняется атомарно в `~/.gemini/antigravity/cache/agy-wake/sessions-<имя_проекта>.json` (не пачкая `git status` репозитория). Если команда хочет хранить реестр в проекте, создай `.agents/agy-sessions.json` через `--registry .agents/agy-sessions.json` - дальше скрипт подхватит его сам.

### 2. Разбудить соседнюю сессию или поставить сообщение в очередь

```bash
# Короткий сигнал спящей сессии (сохраняет модель, выбранную в интерфейсе получателя!)
python3 "<SKILL_DIR>/scripts/agy-wake.py" send \
  --to reviewer \
  --from backend \
  --queue \
  --text "Модуль авторизации готов в src/auth/, тесты зелёные. Проведи ревью." \
  --yes

# Передача развёрнутого задания со списками, кодом и кавычками через файл (рекомендуется!)
python3 "<SKILL_DIR>/scripts/agy-wake.py" send \
  --to qa \
  --from backend \
  --queue \
  --body-file handoff_qa.md \
  --yes
```

**Встроенные предохранители `send`:**
- **Сохранение модели:** если не передан `--model`, скрипт намеренно не отправляет `cascadeConfig`, поэтому у получателя не слетает выбранная в UI модель.
- **Защита занятой вкладки (`--queue`):** если получатель сейчас `RUNNING`, без `--queue` скрипт вернёт отказ, а с `--queue` передаст `MESSAGE_DELIVERY_STRATEGY_WHEN_IDLE` - реплика встанет в штатную FIFO-очередь Antigravity и запустится сразу после завершения текущего хода.
- **Анти-петля (`--cooldown 60`) и запрет самоотправки:** с флагом `--from <роль>` сообщение автоматически подписывается `"от <роль>: ..."`, запрещена отправка самому себе и заблокирован повторный пинг того же адресата чаще раза в 60 секунд (`--no-cooldown` для ручного обхода).
- **Резерв подписочной квоты (`> 10%`):** перед отправкой опрашивается `RetrieveUserQuotaSummary` для пула модели получателя (`Gemini` или `Claude/GPT`). При остатке `<= 10%` автопробуждение останавливается с понятной ошибкой (`--ignore-budget` для явного ручного запуска).

### 3. Создать новую рабочую сессию сразу внутри проекта

Важная тонкость `Antigravity 2.34`: если передать в `StartCascade` поле `workspaceUris`, сессия упадёт в общую кучу `Conversations`, а не в папку проекта `Projects -> <имя>`. Скрипт `agy-wake.py spawn` использует `projectEnvConfig` без `workspaceUris`, поэтому новая вкладка появляется ровно в папке проекта (обязателен стартовый запрос через `--text` или `--body-file`; `--title`, `--slug` и `--preset` опциональны):

```bash
python3 "<SKILL_DIR>/scripts/agy-wake.py" spawn \
  --title "[qa] Тестировщик API" \
  --slug qa \
  --preset turbo \
  --from architect \
  --text "Ты отвечаешь за интеграционные тесты API в папке tests/. Изучи структуру и подтверди готовность." \
  --yes
```

### 4. Удалить временную отладочную сессию

```bash
# Требует полный 36-символьный UUID и статус IDLE (работающую сессию удалить нельзя)
python3 "<SKILL_DIR>/scripts/agy-wake.py" delete --to 00000000-0000-0000-0000-000000000000 --yes
```

## Практика нижнего этажа: постоянные ролевые субагенты внутри сессии

Не выноси каждую мелкую роль в отдельную вкладку левой панели - для команды внутри одного модуля (разработчик, тестировщик, рецензент, документатор) используй постоянных субагентов внутри своей сессии:

1. **Объяви узкую роль** через `define_subagent` (с чётким системным промптом и `EnableWriteTools: false` для рецензента/инспектора или `true` для исполнителя).
2. **Запусти первый раз** через `invoke_subagent` (для быстрых проверок используй `Model: "flash"` - это лёгкая модель `Hydrogen` с окном `512 000` токенов) и **запиши возвращённый `conversationId`** в файл плана задачи.
3. **На следующих итерациях** вызывай `send_message(Recipient="<conversationId>", Message="...")` вместо создания нового субагента:
   - его стенограмма хранится отдельно в `~/.gemini/antigravity/brain/<subagent-id>/`;
   - он помнит весь контекст модуля даже после того, как родительская сессия прошла `/compact` или автосжатие;
   - со второго обращения `88-96%` его входных токенов читаются из горячего промпт-кэша.
4. **Не убивай спящего субагента** через `manage_subagents(Action="kill")` после ответа: в состоянии `idle` он расходует `0` токенов и готов мгновенно продолжить следующий раунд правок.
